Visión General y Objetivos

Esta sección introduce el propósito fundamental del sistema de automatización de video. El objetivo es diseñar un sistema robusto, gratuito y completamente local que permita la edición y generación de videos de manera automatizada. Exploraremos las capacidades clave, desde la manipulación básica de videos hasta la generación de contenido mediante IA y la publicación en diversas plataformas sociales, todo orquestado mediante n8n.

🎯 Objetivo Principal

Diseñar un sistema que, mediante comandos y/o flujos visuales en n8n, permita:

  • Unir y recortar videos.
  • Insertar transiciones, textos, imágenes y audios.
  • Ajustar resolución y tamaño para distintas redes.
  • Generar videos (ASMR, animaciones, explicativos) a partir de prompts de texto.
  • Automatizar desde la búsqueda hasta la publicación en YouTube, Shorts, Facebook, TikTok, Instagram, etc.

🏗️ Pilares del Pipeline

  1. Adquisición: Descarga automática desde fuentes públicas.
  2. Procesamiento y Edición: Transformación, mejora y conversión de formatos, añadiendo valor significativo.
  3. Mejora con IA: Utilización de herramientas de IA para transcripción, generación de voz, y análisis.
  4. Orquestación: Flujos de trabajo programados y basados en eventos utilizando n8n.
  5. Publicación: Subida a plataformas sociales con metadatos optimizados.
  6. Almacenamiento y Versionado: Gestión eficiente de archivos, metadatos y código.
  7. Supervisión y Alertas: Logs, métricas y notificaciones para asegurar la robustez del sistema.
  8. CI/CD y Despliegue: Integración y despliegue continuos para agilizar el desarrollo y mantenimiento.
  9. Documentación: Documentación clara y completa del sistema.

Flujo de Trabajo con n8n

n8n es el corazón de la orquestación en este sistema. Aquí se presenta un ejemplo conceptual de un flujo de trabajo en n8n (representado en YAML) que ilustra cómo se podrían conectar los diferentes pasos del pipeline, desde la activación programada hasta la publicación. También se incluyen mejores prácticas para diseñar flujos robustos y mantenibles en n8n.

📜 Ejemplo de Flujo n8n (YAML Conceptual) (Haz clic para expandir/colapsar)

nodes:
  - id: trigger_schedule
    type: n8n-nodes-base.scheduleTrigger
    typeVersion: 1
    parameters:
      rule: '0 8 * * *' # Ejecución diaria a las 8 AM
    name: "Daily Video Pipeline Trigger"

  - id: set_keywords
    type: n8n-nodes-base.set
    typeVersion: 1
    parameters:
      values:
        string:
          - name: "searchKeywords"
            value: "['ASMR relajación', 'noticias tech', 'tutorial cocina']"
          - name: "videoSourcePath"
            value: "/data/raw/"
    name: "Define Variables de Flujo"

  - id: download_videos_node
    type: n8n-nodes-base.executeCommand
    typeVersion: 1
    parameters:
      command: |
        python /scripts/download_videos.py \
          --keywords "{{ $json.searchKeywords }}" \
          --output "{{ $json.videoSourcePath }}{{ $now.toFormat('yyyyMMdd') }}/"
    name: "1. Descargar Videos"

  # ... más nodos para edición, IA, split, etc. ...

  - id: publish_node
    type: n8n-nodes-base.executeCommand
    typeVersion: 1
    parameters:
      command: |
        python /scripts/publish.py \
          --platforms "youtube,tiktok" \
          --main_video "{{ $json.editedPath }}video.mp4" \
          --credentials_file "/secrets/api_creds.json"
    name: "4. Publicar Contenido"

connections:
  trigger_schedule:
    main:
      - - node: set_keywords
  set_keywords:
    main:
      - - node: download_videos_node
  # ... más conexiones ...
  # (Nodo anterior a publish_node):
  #   main:
  #     - - node: publish_node

Nota: Este YAML es una representación conceptual. La lógica de bucle y el manejo dinámico de nombres de archivo se configuran en la UI de n8n.

💡 Mejores Prácticas para n8n (Haz clic para expandir/colapsar)

Modularidad: Dividir el pipeline en flujos de trabajo más pequeños y reutilizables.

Sub-flujos de Trabajo: Encapsular lógica compleja y repetitiva.

Lógica Condicional: Usar nodos `IF` y `Switch` para enrutamiento dinámico.

Manejo de Errores Robusto: Utilizar "Error Trigger" y ramas de flujo para errores.

Nodos `Wait`: Para respetar límites de tasa de APIs externas.

Control de Versiones: Exportar flujos como JSON y almacenarlos en Git.

Configuración y Despliegue

Esta sección cubre los aspectos prácticos de la puesta en marcha del sistema. Incluye los requerimientos del sistema, un ejemplo de configuración local utilizando Docker Compose, los pasos iniciales para la implementación, y una visión general de cómo se puede integrar un flujo de CI/CD con GitHub Actions.

⚙️ Requerimientos del Sistema (Haz clic para expandir/colapsar)

  • Completamente Local: Procesamiento sin costos recurrentes de nube (salvo opcionales).
  • Modularidad: Pasos encapsulados en contenedores Docker, coordinados por n8n.
  • Acceso CLI y API Local: Scripts ejecutables por línea de comandos.
  • Plantillas de Resolución: Preconfiguraciones para formatos 16:9, 9:16, 1:1.
  • Flujo n8n Detallado: Nodos para descarga, generación, edición, split y publicación.
  • Monitorización y Logging: Registro de logs y métricas básicas.

🐳 Configuración Local con Docker Compose (Ejemplo) (Haz clic para expandir/colapsar)

version: '3.8'
services:
  n8n:
    image: n8nio/n8n
    restart: always
    ports:
      - "5678:5678"
    environment:
      - GENERIC_TIMEZONE=America/Bogota
    volumes:
      - ./n8n_data:/home/node/.n8n
      - ./workflow_scripts:/scripts
      - ./video_data:/data
    # FFmpeg debe estar disponible en la imagen de n8n o en un worker.

  python_worker: # Opcional
    build:
      context: ./python_worker_dir 
    restart: always
    volumes:
      - ./workflow_scripts:/scripts
      - ./video_data:/data

volumes:
  n8n_data:
  video_data:
  workflow_scripts:

Nota: FFmpeg se usaría vía 'docker exec' o, preferiblemente, instalado en el contenedor de n8n/Python.

🚀 Pasos para Implementación Inicial (Haz clic para expandir/colapsar)

  1. Instalar Docker y Docker Compose.
  2. Configurar n8n básico con `docker-compose`.
  3. Desarrollar scripts Python modulares (descarga, edición, IA, publicación).
  4. Crear Dockerfiles para contenedores Python si es necesario.
  5. Diseñar y construir flujos en n8n gradualmente.
  6. Configurar APIs de plataformas sociales y almacenar credenciales de forma segura.
  7. Definir plantillas de edición y realizar pruebas exhaustivas.
  8. Optimizar parámetros y configurar monitoreo básico.
  9. Implementar CI/CD con GitHub Actions.

Consideraciones Críticas

Esta sección aborda puntos cruciales que deben tenerse en cuenta para el éxito y la sostenibilidad del sistema. Incluye el cumplimiento de políticas de contenido, las particularidades de las APIs de las plataformas de publicación, y optimizaciones de rendimiento. Presta especial atención a los elementos marcados para validación.

📜 Política de Contenido Reutilizado (Ej. YouTube)

El contenido debe tener una "transformación significativa" para ser monetizable. No basta con simples re-codificaciones. Se debe añadir valor único como narración, comentario original, edición creativa o elementos visuales dinámicos.

📡 Consideraciones por Plataforma API

TikTok API: Contenido publicado por clientes no auditados queda restringido a visibilidad privada. Se requiere auditoría para publicaciones públicas.
Vimeo API: El plan gratuito es muy limitado (1GB total, sin APIs robustas). Se requerirán planes de pago para uso significativo.
Spotify (Podcasts): La subida se realiza mediante feed RSS desde una plataforma de alojamiento, no directamente con la API Web de Spotify.

Otras APIs (YouTube, Instagram, Facebook, Twitter, LinkedIn) tienen sus propios requisitos de autenticación, cuotas y permisos específicos que deben gestionarse cuidadosamente.

⚡ Manejo de Límites de API y Rendimiento

  • Implementar lógica de reintento con retroceso exponencial.
  • Monitorear encabezados de respuesta de límites de tasa.
  • Usar nodos "Wait" en n8n para espaciar solicitudes.
  • Optimizar FFmpeg: usar presets, ajustar CRF, paralelizar con threads, considerar aceleración por GPU.
  • NAS (SMB/CIFS): Optimizar configuración o usar DAS para tareas intensivas.

Monitoreo, Logging y Mantenimiento

Para asegurar la fiabilidad y eficiencia del sistema a largo plazo, es fundamental implementar buenas prácticas de monitoreo, logging y mantenimiento. Esta sección describe las estrategias y herramientas recomendadas para estas tareas, incluyendo la gestión de errores y la documentación del sistema.

📝 Logging

  • Utilizar logging estructurado en Python (JSON).
  • Establecer niveles de logging adecuados (DEBUG, INFO, WARNING).
  • Revisar logs de n8n y contenedores Docker.
  • Considerar centralización de logs (SigNoz, Loki, ELK Stack) para sistemas grandes.

📊 Métricas y Seguimiento de Errores

Métricas clave: tiempos de procesamiento, videos procesados, tasas de error, uso de recursos.

  • Herramientas: Prometheus y Grafana para métricas y visualización.
  • Sentry para seguimiento de errores.
    Sentry (Nivel Gratuito): Limitado (1 usuario, 5k errores/mes). Considerar self-hosted o alternativas (SigNoz, Zabbix) si es insuficiente.

🔔 Mecanismos de Alerta

  • Notificaciones de n8n para fallos en flujos.
  • Alertas por correo electrónico (Python `smtplib` o servicios de API).
  • Integración con mensajería (Slack, Discord) vía webhooks.
  • Alertas desde sistemas de monitoreo (Grafana, Sentry).
